### 3) Rủi ro/điểm yếu

1. **Slow consumer chưa có giới hạn rõ ở điểm phát:** WS chỉ kiểm tra readyState rồi send, không kiểm tra bufferedAmount tại helper này. SSE live gọi write không await; trong replay, live event dồn vào mảng không có trần. Rủi ro tăng RAM khi client/disk/network lệch tốc độ là suy luận tĩnh, chưa chứng minh bằng tải (`packages/work/src/server/ws.ts:139`, `packages/work/src/server/routes/sse.ts:49`, `packages/work/src/server/routes/sse.ts:63`).
2. **Cursor replay có thể giữ nguyên suffix trong RAM:** `readEventsAfterLiveCursor` nối toàn bộ byte từ offset vào string rồi split/map thành array; không truyền abort signal từ SSE vào reader này. Cursor cũ trên nhật ký lớn có thể tốn RAM dù history page đã tối ưu; đường không cursor stream từng event nhưng vẫn duyệt file để lọc seq (`packages/work/src/runs/event-history.ts:818`, `packages/work/src/runs/event-history.ts:834`, `packages/work/src/server/routes/sse.ts:77`, `packages/work/src/server/routes/sse.ts:83`).
3. **Atomicity không đồng nghĩa cùng chuẩn durability/quyền file:** workspace helper mở mode 0600 và fsync; run index temp và append event không chỉ định mode hay fsync ở các call site đã đọc. Quyền thực tế phụ thuộc umask/ACL/thư mục cha; chưa kiểm tra quyền file runtime, không kết luận có lộ dữ liệu. Chênh lệch đáng chú ý vì history/index chứa nội dung task (`packages/work/src/workspace/config.ts:488`, `packages/work/src/workspace/config.ts:490`, `packages/work/src/runs/store.ts:1751`, `packages/work/src/runs/store.ts:2297`).
4. **Đồng thời nhiều process có giới hạn được ghi nhận:** run index merge field vẫn last-writer-wins cho cùng field, chỉ lastViewedSeq monotonic; durable tombstone liên process chưa có. Workspace path queue chỉ bảo vệ trong process, comment thừa nhận cửa sổ read→rename giữa process. Không nên gọi các cơ chế này là transaction xuyên process hoàn chỉnh (`packages/work/src/runs/store.ts:2315`, `packages/work/src/workspace/config.ts:541`, `packages/work/src/workspace/config.ts:555`).
5. **Degrade có thể làm lịch sử thiếu:** access-denied khiến event sống trên stream nhưng chưa xuống disk; index reader gặp schema lỗi trả toàn bộ danh sách rỗng. Đây là thiết kế tiếp tục hoạt động, nhưng người dùng có thể thấy task biến mất/không replay đủ nếu thiếu trạng thái giải thích (`packages/work/src/runs/store.ts:1753`, `packages/work/src/runs/store.ts:1763`, `packages/work/src/runs/run-index.ts:28`).
6. **Validation có chi phí và duplication:** JSON guard tự JSON.parse trước khi giao lại Hono validator trên đường JSON chuẩn; cần xem dependency được pin để xác nhận có parse lần hai, chưa kết luận từ riêng wrapper. Một request có thể tới trần toàn cục 32 MiB. Schema được khai báo ở contract và payload handler vẫn phải đối chiếu parity; nhiều family lớn tăng diện tích drift (`packages/work/src/server/validators.ts:129`, `packages/work/src/server/validators.ts:136`, `packages/work/src/server/server.ts:686`, `packages/work/src/server/contract-parity.test.ts:15`; số đo tệp lớn ở mục 2).
7. **Parity chủ yếu bảo vệ kiểu, không chứng minh tải:** comparator contract và typed-bodies do tsc thực thi; runtime test cho route/SSE có tồn tại nhưng không được chạy trong lượt này. Phạm vi: đọc tĩnh mã nguồn, cấu hình, tài liệu và lịch sử Git; không chạy test, build hay typecheck. Mọi số lượng tệp test là đếm tên tệp, không phải số test case. Quy mô repo đo trên checkout hiện tại bằng danh sách git ls-files và kích thước tệp đang tồn tại.

### 1) Chức năng hiện có

- OnniCode là cockpit local-first: Node 20+, Hono/SSE/WebSocket, hợp đồng Zod và SPA React/Vite; state nằm ở JSON/NDJSON/Markdown, không dùng account/cloud/database theo kiến trúc hiện hành (AGENTS.md:1-15,42-63; packages/work/src/index.ts:281-290).
- Bốn npm workspace là work, contract, api-client và web; desktop Tauri cố ý đứng ngoài root workspace để không kéo Tauri CLI vào engine/cockpit (package.json:11-16; AGENTS.md:44-53). Engine có CLI/API, workflow graph, registry/worktree và RunManager; runner factory đăng ký backend từ schema chia sẻ (packages/work/src/index.ts:65-72,281-290; packages/work/src/core/runner-factory.ts:20-48; packages/contract/src/health.ts:4).
- Giao diện cung cấp task/thread, workspace và settings; api-client chia sẻ schema, URL scope và giao thức UI/tool/webhook events với browser (packages/web/src/app.tsx:30; packages/api-client/src/index.ts:26-31; packages/contract/src/index.ts:5-43).
- Orchestration có worktree riêng mỗi task, workflow YAML/graph, task dispatch/manager-worker, lịch chạy/automation GitHub và tracker, webhooks, secrets và giới hạn run (AGENTS.md:117-158; docs/reference.md:645-651; docs/reference.md:564-570; .github/workflows/ci.yml:75-81).
- Hàng rào vận hành gồm pre-push hook cho run unattended, kiểm tra runner trong roster, budget/depth/subtask limits và mức quyền Antigravity theo loại run (packages/work/src/workflows/push-guard.ts:5-24,32-44,65-99; packages/work/src/workflows/unattended.ts:4-9; packages/contract/src/roster.ts:16-34; packages/work/src/core/antigravity-permissions.ts:49-64,135-151).
- Desktop Tauri đóng gói cửa sổ cho cockpit và giám sát Node sidecar, đợi health endpoint, chọn bản engine đã link; capability cho webview được mô tả trong cấu hình Tauri (packages/desktop/package.json:5,14-24; packages/desktop/src-tauri/src/lib.rs:1-20,710-790; packages/desktop/src-tauri/tauri.conf.json:3-19; packages/desktop/src-tauri/capabilities/default.json:2-18).
- Dependency trực tiếp theo manifest: work có 11 runtime (Hono/node-server, Zod, YAML, TOML, HTTP/WebSocket, lockfile, Tree-sitter và CLI prompts) cùng 2 optional (PTY, keyring); web có 24 runtime chủ yếu React/router/query, graph/drag-drop, terminal, syntax/Markdown rendering và Tailwind; contract chỉ cần Zod; api-client cần contract+Hono; desktop có Tauri CLI ở devDependencies (packages/work/package.json:45-77; packages/web/package.json:15-52; packages/contract/package.json:17-20; packages/api-client/package.json:23-30; packages/desktop/package.json:23-25). Root giữ toolchain/test/build và 4 workspaces, không đóng gói desktop vào npm install (package.json:11-16,40-51; AGENTS.md:52-53).

### 2) Đánh giá hiệu quả

- Quy mô checkout đo được: 2.524 tệp tracked, 35.714.522 byte tệp tracked hiện có (~34,1 MiB), trong đó 20.677.597 byte ở các cây source chính; source inventory gồm 1.051 work, 874 web, 39 contract, 9 api-client và 3 Rust desktop source files. Phép đo là static; không gồm file build chưa tracked hay node_modules (git ls-files + kích thước tệp hiện tại; package.json:11-16).
- Đếm tệp test tĩnh: 893 Vitest *.test.*, 7 node:test unit, 3 node:test package E2E, 42 browser *.e2e.*; desktop có 1 tệp Rust chứa test. Các loại test phân biệt theo quy ước thư mục/tên file, không phải test case; không chạy test theo yêu cầu (package.json:28-38; packages/work/package.json:35-42; packages/web/e2e/; packages/desktop/src-tauri/src/lib.rs:2185-2706).
- CI có ba workflow: CI chia Vitest thành 3 shard và tách verify; CodeQL quét JavaScript/TypeScript cùng GitHub Actions theo lịch tuần; desktop-check chạy cargo check/test Linux+Windows và có bước npm kiểm tra engine/runner khi đường dẫn thay đổi (.github/workflows/ci.yml:24-47,49-81,94-133; .github/workflows/codeql.yml:4-15,25-45; .github/workflows/desktop-check.yml:11-55,65-130). CI comment ghi Vitest trước đây chiếm khoảng 8/9 phút nên shard chạy song song (ci.yml:24-27); đây là số lịch sử ghi trong workflow, không phải phép đo lần này.
- Đồng bộ live dùng một WebSocket theo dõi nhiều topic; server publisher chỉ chạy khi topic có subscriber, heartbeat 30 giây và giới hạn payload 4 KiB (packages/work/src/server/ws.ts:7-20,36-40,54-57). Còn polling có chủ đích khi run active: changes mỗi 4 giây, git status mỗi 10 giây, commits mỗi 5 giây; GitHub ref status dùng nhịp do server trả và không chạy nền khi tab ẩn (packages/web/src/api/queries.ts:1204-1207,1224-1227,1274-1278,2286-2293).
- RunManager cài watchdog hàng đợi 60 giây và quét giới hạn mỗi 15 giây; đây là timer nền nhỏ nhưng tồn tại khi manager còn sống (packages/work/src/workflows/run.ts:946-949,1380-1382). Run history append event đồng bộ qua appendFileSync; snapshot save được debounce timer, giảm ghi lặp JSON trong burst (packages/work/src/runs/store.ts:1751-1766,2278-2284).
- Các điểm tập trung lớn: run.ts 3.473 dòng, server.ts 2.648, store.ts 2.443, web API client 3.042, queries.ts 2.428, desktop lib.rs 2.770; run.test.ts 3.802 dòng và github.test.ts 3.471 dòng. Run.ts ghi nhận hai handler kết thúc lượt gần giống nhau và đã chia helper cho logic chung, nên đây là vùng có chi phí review/regression cao nhất (đếm dòng tĩnh; packages/work/src/workflows/run.ts:589-610,1607; packages/work/src/server/server.ts; packages/work/src/runs/store.ts; packages/web/src/api/client.ts; packages/web/src/api/queries.ts; packages/desktop/src-tauri/src/lib.rs; packages/work/src/workflows/run.test.ts; packages/work/src/server/forge/github.test.ts).
- .env.example có 69 tên biến cấu hình/commented example; quét tĩnh cây TS/Rust bắt gặp 112 tên ONNI/AGY/VITE_ONNI, còn reference có 68 tên phân biệt. Hai tập có khác phạm vi do runtime metadata, biến mock/test/desktop và flag cho người vận hành; ví dụ ONNI_CODEX_REASONING, ONNI_CONTEXT_COMPACTION, ONNI_FAILOVER hiện có mô tả trong .env.example nhưng không nằm trong bảng environment hữu ích của docs/reference (đối chiếu .env.example:38,84,230,238; docs/reference.md:553-605; docs/FEATURES.md:118). Vì vậy tổng số không tự chứng minh thiếu biến, nhưng việc phân loại chưa có kiểm tra tự động (AGENTS.md:16-39).

### 3) Rủi ro/điểm yếu

- Tài liệu FEATURES là ảnh chụp ngày 2026-10-30 và danh sách 8 backend thiếu Cline; hợp đồng hiện có 9 runner gồm Cline và Antigravity. Dùng bảng này như inventory hiện hành sẽ làm sai phạm vi tính năng (docs/FEATURES.md:3,101; packages/contract/src/health.ts:4; AGENT_PROTOCOL.md:38).
- README của specs đã cảnh báo specs có tên cũ/tính năng đã gỡ và xếp code → AGENTS → docs → specs theo độ ưu tiên. Rủi ro còn lại là người đọc bỏ qua cảnh báo và coi spec lịch sử là trạng thái đang chạy (.ai/specs/README.md:10-29).
- Push guard là fence, không phải sandbox: hook cho phép refs onni/* và cho phép bypass qua --no-verify, bỏ biến cấu hình, sửa hooksPath hoặc đẩy qua công cụ ngoài Git; deny-list Bash riêng hiện nêu rõ Claude (packages/work/src/workflows/push-guard.ts:5-24,94-99). Roster cũng không giới hạn lệnh/API trực tiếp của agent (packages/contract/src/roster.ts:6-9).
- Antigravity allow-rules chỉ cấp lệnh shell nguyên dòng; tài liệu repo nói công cụ file/web riêng của agent không bị giới hạn bởi rules, còn runner này chưa được phép làm manager vì chưa xác minh command workflow đầy đủ (packages/work/src/core/antigravity-permissions.ts:46-64,86-116; packages/contract/src/roster.ts:16-34; AGENTS.md:176-183).
- .env.example giải thích nhiều cờ nhưng docs/reference không gom hết các flag vận hành; quét đối chiếu thấy nhóm trên cùng desktop/debug flags không có tên trong bảng reference. Việc “một biến mới phải được cập nhật example” được nêu rõ trong quy tắc repo, nhưng không thấy phép kiểm tra tĩnh trong ba workflow đã khảo sát (AGENTS.md:35-39; .env.example:38,84,137,230,238; docs/reference.md:553-605; .github/workflows/ci.yml:24-133).
- Desktop nằm ngoài npm workspaces, nên root install/typecheck/build không bao phủ shell; repo bù bằng workflow riêng, nhưng workflow chỉ chạy khi path filter khớp hoặc dispatch thủ công (AGENTS.md:52,68-76; .github/workflows/desktop-check.yml:11-55,65-130).
- Không đánh giá pass/fail runtime được trong survey này vì yêu cầu cấm chạy test/build/typecheck; các số test trên chỉ nói lượng tệp và cấu hình CI, không chứng minh chất lượng thực thi (AGENTS.md:68-80; .github/workflows/ci.yml:24-133; .github/workflows/desktop-check.yml:104-130).

### 4) Hướng phát triển đề xuất

- P0 — Không xác nhận vấn đề cần sửa khẩn cấp bằng khảo sát tĩnh; không suy diễn mức độ ưu tiên từ bằng chứng chưa có kiểm chứng runtime (phạm vi khảo sát; AGENTS.md:68-80).
- P1 — Đồng bộ inventory tài liệu trước khi dùng để ra quyết định: cập nhật FEATURES với ngày chụp, runner 9 backend và trạng thái bằng chứng kiểm thử; giữ cảnh báo lịch sử ở specs. Lý do: ảnh chụp 30/10 thiếu Cline so với contract hiện tại (docs/FEATURES.md:3,101; packages/contract/src/health.ts:4; .ai/specs/README.md:24-29).

- P1 — Tự động đối chiếu environment docs: thêm checker tĩnh phân loại operator config, runtime-injected và test-only; so tên/ý nghĩa .env.example với bảng docs/reference và flag được code đọc, báo diff trong CI thay vì buộc reviewer dò tay. Ưu tiên vì hiện có chênh nhóm biến và repo yêu cầu cập nhật đồng bộ (AGENTS.md:35-39; .env.example:38,84,230,238; docs/reference.md:553-605).
- P1 — Tiếp tục kiểm tra defense-in-depth theo backend: tài liệu hóa rõ fence khác sandbox và ghi test/CI về nhánh push qua Git lẫn tool/API khác; giữ Antigravity worker-only đến khi quyền file/web và lệnh manager được xác nhận. Không mở thêm quyền mặc định vì code hiện đã mô tả rõ các bypass và giới hạn (packages/work/src/workflows/push-guard.ts:5-24,94-99; packages/contract/src/roster.ts:16-34; AGENTS.md:162-183).
- P2 — Tách module theo ranh giới khi có thay đổi chức năng: chia dần run orchestration/server/query logic, ưu tiên các file trên 2.400 dòng; giữ hai luồng turn-end đồng bộ hóa qua helper và kiểm tra behavior từng bước, không làm một đợt thay thế cơ chế (packages/work/src/workflows/run.ts:589-610,1607; packages/work/src/server/server.ts; packages/web/src/api/queries.ts; AGENTS.md:186-220).
- P2 — Đo chi phí thật trước khi tối ưu: lưu thời lượng từng CI shard, kích thước asset Vite sau build và số truy vấn Git/FS theo active run để đặt baseline; hiện survey chỉ có ngưỡng polling trong code và ghi chú lịch sử 8/9 phút, không có phép đo bundle/runtime mới (packages/web/package.json:8-14; packages/web/src/api/queries.ts:1204-1207,1224-1227,1274-1278; .github/workflows/ci.yml:24-27).
